Git saves the commits. Who saves the rest?

Between two commits sit hours of edits, experiments and AI changes. Git never sees them. Delete a file, let an agent rewrite it, or overwrite it by mistake, and that work is gone.

How a save becomes a snapshot.

Every time you save a source file, six things happen in about a second. Nothing leaves your machine.

Watch it happen in the dashboard
  1. 1

    Watch

    The watcher notices a save anywhere in your project.

    modified src/app.js
  2. 2

    Wait

    It waits a second for the editor to finish writing, so one save is one snapshot.

  3. 3

    Hash

    The content gets a SHA-256 fingerprint.

    sha256 b0103817464bb37c4ab66446…
  4. 4

    Skip duplicates

    Identical content is skipped, so saving twice costs nothing.

  5. 5

    Store

    An atomic copy lands in the project’s vault folder, with a row in SQLite.

    .lifejacket/snapshots/src/app.js.20261104_140612.bak
  6. 6

    Keep it tidy

    Ten snapshots per file for thirty days by default. Pinned ones stay forever.

Know which disks GitHub has.

CodeVault compares every snapshot with your git history and colours it, so you can see which work would be lost if this laptop died tonight.

AI edits get a yellow label.

Claude Code, Antigravity and other agents write straight to your files. With one command, CodeVault snapshots each file right before and right after every Claude edit, and labels who made it.

$ codevault hooks install claude .
[OK] Claude Code will now snapshot files before and after each edit in ~/assignment-3

For tools without hooks: codevault snapshot . --source antigravity --note "before agent run"

auth.pyclaude · before edit · 14:02
auth.pyclaude · edit · 14:02

Put any disk back.

Pick a snapshot, see exactly what changed, then restore. The file you replace becomes a snapshot first, so a restore can always be undone. Slide a disk’s write-protect tab, which is pinning it, and cleanup never removes it.
